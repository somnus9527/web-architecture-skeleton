# Todo 工作流规则

## 目的

本文档是 React Native 项目使用的 todo 工作流规则，用于让 todo 文件保持轻量，同时把详细执行证据保存在默认恢复路径之外。

## 文件职责

`docs/*-todo.md` 下的 todo 和 plan 文件是任务索引。它们只应包含选择下一个 slice 和判断是否完成所需的信息：

- 任务 id
- 标题
- 状态
- 简短范围
- 完成条件
- 验证命令
- 最新证据摘要
- 详细执行记录链接

详细执行记录放在：

```text
docs/executing-list/<todo-file-stem>/<task-id-or-date-slug>.md
```

不要把长命令输出、重复历史总结、大段调查日志或详细实现记录直接写入 todo 文件。

## Todo 条目格式

待处理任务：

```markdown
- [ ] P1.2 任务标题
  - 范围：一句话说明范围。
  - 完成条件：具体完成条件。
  - 验证：`command`
  - 记录：`docs/executing-list/<todo-file-stem>/P1.2-task-title.md`
```

已完成任务：

```markdown
- [x] P1.2 任务标题
  - 证据：简短结果摘要、日期和关键命令名。
  - 记录：`docs/executing-list/<todo-file-stem>/P1.2-task-title.md`
```

## 执行记录格式

```markdown
# P1.2 任务标题

## 上下文

- 来源 todo：`docs/example-todo.md`
- 状态：进行中 | 已完成 | 阻塞
- 最近更新：YYYY-MM-DD

## 范围

- 本 slice 包含什么。
- 本 slice 明确不包含什么。

## 工作记录

- YYYY-MM-DD: 简短实现或调查记录。

## 决策

- 可复用的决策及原因。

## 验证

- `command`
  - 结果：通过 | 失败 | 未运行
  - 说明：简短说明或截断后的输出片段。

## 后续事项

- 剩余工作；如果尚未被跟踪，应拆成独立 todo。
```

## 恢复规则

继续 checklist 或 todo 时：

1. 读取 `AGENTS.md` 入口与相关 `docs/rules/rn/*.md` 规则。
2. 读取权威 todo 文件。
3. 找到下一个未完成或用户明确指定的任务。
4. 只在存在且当前任务需要时读取该任务的执行记录。
5. 除非当前任务依赖旧记录，或用户要求审计，否则不要批量读取已完成历史记录。

## 更新规则

- 开始 slice 前，如果需要记录紧凑 todo 行之外的信息，创建或更新对应执行记录。
- 完成 slice 后，把详细工作记录、决策、验证证据和后续事项写入执行记录。
- todo 文件只更新状态、短证据摘要和记录链接。
- 只有相关验证通过，或用户明确接受已记录的例外时，才能标记 todo 完成。
- 如果任务被阻塞，todo 行保持简短，诊断写入执行记录。

## 重构大型 Todo

当 todo 文件过大时：

1. 保留任务 id 和勾选状态。
2. 将详细历史记录迁移到 `docs/executing-list/<todo-file-stem>/`。
3. 用简短“证据”或“记录”行替换被迁移内容。
4. 保留足够摘要，使后续无需读取旧记录也能选择下一个任务。
5. 验证链接指向新的记录文件。

除非用户明确要求丢弃，否则不得静默删除执行历史。
