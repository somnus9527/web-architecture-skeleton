# 国际化规则

## 目的

本文件描述 React Native 项目的 i18n 框架、locale 切换、fallback、文案组织与 RTL 基线。

## 框架

- 使用 `i18next` + `react-i18next`（最新稳定版）。
- locale 文案文件位于 `src/domain/locale/messages/locales/<locale>.json`。
- locale 别名、fallback、归一化逻辑维护在 `src/domain/locale/constants.ts` 与 `src/domain/locale/i18n.ts`。
- locale 切换 store：`src/domain/locale/locale-store.ts`。
- 完整初始化模版见 `docs/rules/rn/templates/i18n-setup.md`。

### Locale 基线

- 目标 locale 清单以 `src/domain/locale/constants.ts` 的 `supportedLocales` 为准。
- 实际维护的静态词典由 `src/domain/locale/messages/index.ts` 的 `localeMessageDictionaries` 固定；未完整维护的目标 locale 必须通过 i18next fallback 展示默认语言，不允许假装已有完整翻译。
- 新增目标语言时，先补对应 `<locale>.json`、词典 key 对齐测试与语言切换展示配置，再把该 locale 从 fallback 状态提升为完整维护状态。

## 用户可见文案

### 必须 i18n

所有用户可见文案必须放在 locale 文件中，通过 `useTranslation()` 或等价 helper 读取。**禁止硬编码**任何用户可见字符串（≥ 2 字符 + 出现在 JSX 文本节点）。

```tsx
// 禁止
<Text>请填写邮箱</Text>
<Text>Welcome</Text>

// 推荐
const { t } = useTranslation();
<Text>{t('auth.email.required')}</Text>
```

### 例外

- testID、accessibilityRole 字符串。
- 路由 pathname 字符串字面量。
- 日志 message（dev only，redact 见 `docs/rules/rn/observability.md`）。
- 调试 console 文案（仅 dev 可见）。
- 业务编码 / status 字面量（如 `'paid'` / `'cancelled'`）。

## 文案 Key 命名

- 使用扁平 JSON key，通过点号表达语义层级：`feature.subfeature.key`：`auth.login.title`、`feature.empty.description`、`form.submit`。
- 不允许深度超过 4 层。
- 不允许 key 中出现内容字符串（如 `errors.your-account-is-locked`）；用语义名（`errors.accountLocked`）。
- key 全英文 kebab 或 camelCase；遵循 i18next 风格。

## 文案文件结构

```json
// src/domain/locale/messages/locales/zh_CN.json
{
  "auth.login.title": "登录",
  "auth.login.emailLabel": "邮箱",
  "feature.empty.title": "暂无数据"
}

// src/domain/locale/messages/locales/en_US.json
{
  "auth.login.title": "Sign in",
  "auth.login.emailLabel": "Email",
  "feature.empty.title": "No data yet"
}
```

## Fallback 链路

### 默认链路

`<请求 locale> → <语言基础 locale> → en-US` → 找不到 key 时返回 key 本身（dev）或 fallback 文案（prod）。

运行时 fallback 由 `src/domain/locale/i18n.ts` 配置：

- 默认：任意未维护 locale → `en-US`。
- `zh-TW`：先 fallback 到 `zh-CN`，再 fallback 到 `en-US`。

### Locale 别名

`src/domain/locale/constants.ts` 维护别名表：

```ts
export const localeAliases: Record<string, string> = {
  'zh-Hans': 'zh-CN',
  'zh-Hant': 'zh-TW',
  en: 'en-US',
  // ...
};
```

### Key 缺失处理

- dev：`return missingKey`（直接渲染 key 名），并 `logger.warn` 提示。
- prod：fallback 到 en 或返回空字符串（视产品决策）。
- 一定不要让 key 缺失导致 React render error。

## 复数与插值

### 复数

使用 i18next 复数规则：

```ts
// 文案
{
  feature: {
    itemCount_one: '{{count}} item',
    itemCount_other: '{{count}} items',
  },
}

// 调用
t('feature.itemCount', { count: items.length });
```

### 插值

```ts
// 文案
{
  welcome: '你好，{{name}}';
}

// 调用
t('welcome', { name: user.name });
```

- 插值变量必须经过 escape（i18next 默认开启）。
- 不允许把整段 HTML 通过插值传入；视觉富文本用组件拼接。

## Locale 切换

通过 `useLocaleStore` 切换 locale：

```tsx
const { locale, setLocale } = useLocaleStore();

<Picker selectedValue={locale} onValueChange={setLocale}>
  <Picker.Item label="简体中文" value="zh-CN" />
  <Picker.Item label="English" value="en-US" />
</Picker>;
```

切换后：

1. i18next instance 更新。
2. 持久化到 AsyncStorage（key 通过 `<app-namespace>.locale`；详见 `docs/rules/rn/storage.md`）。
3. 触发依赖 locale 的 query refetch（query key 包含 locale）。

## 数字 / 日期 / 货币格式化

### 货币

通过 `@domain/locale/price-format` 中的 `formatPrice(amountUsd, currency)` 转换；不在组件内手写 `toFixed`。UI 层优先使用 `@components/ui/price`，保持币种符号、静态汇率、小数位和 `Intl.NumberFormat.formatToParts` fallback 一致。

```tsx
import { Price } from '@components/ui/price';

<Price amountUsd={plan.price} currency={currency} />;
```

### 日期 / 时间

使用 `Intl.DateTimeFormat`，并把格式化封装到 domain 或同目录 `tools.ts`，不要在 JSX 中直接拼日期字符串。

```ts
new Intl.DateTimeFormat(locale, {
  year: 'numeric',
  month: 'short',
  day: 'numeric',
}).format(new Date(entity.createdAt));
```

### 数字

普通数字使用 `Intl.NumberFormat`，货币数字仍走 `@domain/locale/price-format`：

```ts
new Intl.NumberFormat(locale).format(itemCount);
```

不要直接调用 `toLocaleString` / `toLocaleDateString` / `toLocaleTimeString` 写业务展示；如果 Native 运行时缺少某个 `Intl` 能力，先在对应 formatter 中集中加 fallback，并在 `docs/rules/rn/dependencies.md` 记录运行时约束。

## RTL 支持

### 默认基线

默认不启用 RTL。项目如未来启用：

1. 在 `src/domain/locale/constants.ts` 标记 RTL locale 列表（`ar`、`he` 等）。
2. App 启动时按 locale 调 `I18nManager.forceRTL(true)` + `Updates.reloadAsync()`（需要重启）。
3. 所有 `flexDirection: 'row'` 自动镜像；但 `marginLeft` / `marginRight` 需要替换为 `marginStart` / `marginEnd`。
4. 图标方向、滚动方向需要审视。

### 触发启用条件

- 业务确认目标市场含 RTL 语言用户。
- UI 团队完成 RTL 设计稿。
- QA 流程加 RTL 双语种回归。

## 测试

### Locale 测试

- 关键路径在 `src/test/components/<feature>/*.test.tsx` 中至少覆盖 1 种 locale（zh 或 en）。
- locale fallback 链路在 `src/test/domain/locale/*.test.ts` 中覆盖。
- 缺失 key 测试：构造 missing key 场景，断言不 throw + dev 下 warn。

### Hardcoded 扫描

可选架构测试 `src/test/architecture/hardcoded-copy-boundary.test.ts`：扫描 `src/components/**/*.tsx` 中 JSX text 节点出现的中英文长字符串（≥ 6 字符）；存在违规列入 follow-up。

## 完成检查

- 所有用户可见文案走 `t('key')`，不硬编码。
- key 命名层级化、语义化。
- 复数 / 插值通过 i18next 标准 API。
- 货币 / 日期 / 数字 走 formatter，不手写。
- 关键路径测试覆盖至少 1 种 locale。
- RTL 启用前先评估，再实施。
